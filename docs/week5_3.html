Random Forests

Today’s Lecture

In today’s lecture we will cover:

  • Why bagging is not enough
  • The idea behind random forests
  • The random forest algorithm
  • Out of bag error and variable importance
  • Tuning a random forest
  • Random forests in R

Why Random Forests?

Random forests are among the most successful and widely used machine learning models. Many people treat them as the default first model for prediction from tables of data, because they:

  • need little tuning,
  • handle nonlinear effects and interactions on their own,
  • work with both categorical and continuous predictors, and
  • hold up well against noise and overfitting.

Where We Left Off

Random forests build directly on the last two lectures, so we start with a quick recap: a single decision tree, then bagging.

  • Why does a single tree overfit?
  • Why does averaging many trees help?

Recap: A Single Decision Tree

  • A tree grows by greedy splits: at each node, it takes the split that most reduces impurity.
  • cp limits its size, and cross validation chooses cp. Our tree had 4 leaves, split first on OPN1, and reached a test Kappa of 0.469.
  • Its weakness is instability. Depending only on how the folds were drawn, cross validation chose trees with anywhere from 2 to 17 leaves.

Recap: Bagging

Bagging, short for bootstrap aggregating, fixes that instability by averaging:

  1. Draw many bootstrap samples: each the same size as the data, sampled with replacement.
  2. Grow a deep, unpruned tree on each sample. Each tree has low bias and high variance.
  3. Combine the trees: majority vote for classification, average for regression.

Each tree overfits its own sample in its own way. Averaging many of them cancels out much of that variance.

How the Trees Combine

Here is one new respondent passed through 5 bagged trees. Each tree classifies the respondent on its own, and then we count the votes.

  • Each tree sends the respondent down to one leaf. The most common class in that leaf is the tree’s vote.
  • The class with the most votes wins. Here 4 of the 5 trees vote 1, so we predict OPN8 = 1.
  • The share of votes, 4 out of 5 or 0.80, serves as the predicted probability.
  • For regression, we average the trees’ predicted numbers instead. Random forests combine their trees the same way.

Recap: Bagging on the Personality Data

Test set Single tree 100 bagged trees
Accuracy 0.741 0.774
Kappa 0.469 0.543
Sensitivity 0.654 0.752
Specificity 0.810 0.792
  • Each bagged tree had more than 80 leaves. Any one of them overfits, but the average of 100 predicted better than the single pruned tree.
  • The out of bag error was 0.28, so about 72% of observations were classified correctly by the trees that never saw them.
  • The cost: there is no longer a single tree to read.

Bagging Looks Like Cross Validation

Both methods fit many models, each on part of the data, and keep the rest for checking. Here are 20 observations, split up for 5 models each way.

  • In cross validation, every column has exactly one orange cell.
  • In bagging, the orange cells fall at random, about 37% of each row, and some observations are drawn two or three times (the numbers).

Same Idea, Different Goal

\(k\) fold cross validation Bagging
Each model is fit on \(k - 1\) of the \(k\) folds a bootstrap sample, with repeats
Held out from each model one fold, \(1/k\) of the data the out of bag observations, about 37%
Each observation is held out exactly once by about 37% of the models
The models are then used to estimate error, then set aside averaged into the final prediction
The held out data give us the cross validation error the out of bag error

The key difference: cross validation fits models to measure a method, and bagging fits models to become the method. The out of bag error is a cross validation estimate that bagging gives us for free.

If the out of bag error comes for free, why do we still use cross validation?

One Problem Remains

All 100 bagged trees split first on OPN1.

  • In bagging, every tree can choose from every predictor at every split.
  • A strong predictor like OPN1 wins the first split in nearly every bootstrap sample, so the trees end up looking alike.

If every tree starts with the same question, how different can their predictions be?

Why Are Similar Trees a Problem?

When the trees look alike, they make similar predictions, and similar mistakes. How much averaging helps depends on two things:

\[ \text{Var}(\bar{f}) \approx \rho \sigma^2 + \frac{(1 - \rho)\sigma^2}{B} \]

  • \(\sigma^2\) is the variance of each tree,
  • \(\rho\) is the correlation between the trees’ predictions, and
  • \(B\) is the number of trees.

Adding trees shrinks only the second term. If \(\rho\) is large, the first term dominates, and more trees barely help. Averaging 100 identical trees gives you the same tree.

How Can We Fix This?

Make the trees less alike by adding randomness to how each one is grown.

Random forests do this by choosing a random subset of predictors at each split. Then:

  • different trees see different predictors,
  • they grow differently,
  • their errors are less correlated, and
  • averaging them reduces variance much more.

A Brief History

  • In 1995, Tin Kam Ho at Bell Labs grew trees on random subsets of the predictors and combined them, calling the result “random decision forests.”
  • In 1997, Yali Amit and Donald Geman used randomly chosen splits to build many trees for recognizing handwritten shapes.
  • In 2001, Leo Breiman, who had introduced bagging in 1996, combined bagging with random predictor subsets at each split in his paper “Random Forests.” He also showed how to use the out of bag observations to estimate error and variable importance.

Breiman’s version is the one in nearly every software package today.

What Is a Random Forest?

A random forest is an ensemble of decision trees, each trained on:

  • a different bootstrap sample of the data, like bagging, and
  • a random subset of the predictors at each split.

Each tree makes a prediction, and the forest combines them:

  • by majority vote for classification, and
  • by averaging for regression.

A Random Subset of Predictors

A single tree, and every bagged tree, searches all predictors for the best split. A random forest changes this one step:

  • At each split, draw a random subset of \(m\) predictors.
  • Find the best split among those \(m\) only.

Typical defaults, where \(p\) is the number of predictors:

  • classification: \(m = \sqrt{p}\)
  • regression: \(m = p / 3\)

With \(m = p\), a random forest is the same as bagging.

Random Predictors at Each Split

Six trees pick their first split from the same 9 predictors, listed from strongest to weakest. A random forest with \(m = 3\) draws 3 of them per split.

  • Bagging: OPN1 can always be used, so it wins the first split of every tree.
  • Random forest: OPN1 is drawn for about 1 in 3 splits. The rest of the time, the best predictor in the subset wins.
  • A new subset is drawn at every split, so a tree can still use OPN1 further down.
  • The trees end up less alike, so their mistakes overlap less.

The Random Forest Algorithm

Given training data with \(n\) observations and \(p\) predictors:

  1. Choose the number of trees, \(B\).
  2. For each tree \(b = 1, 2, \ldots, B\):
    1. Draw a bootstrap sample from the training data.
    2. Grow a tree on that sample. At each node:
      • randomly select \(m\) predictors,
      • choose the best split among them, and
      • keep splitting, with no pruning.
  3. Combine the trees: majority vote for classification, average for regression.

Out of Bag Error

As in bagging, each tree is trained on a bootstrap sample, about 63% of the observations. The other 37% are out of bag for that tree.

  • For each observation, predict its outcome using only the trees that did not see it.
  • The resulting out of bag error estimates error on new data, without setting aside a separate validation set.

Variable Importance

A forest has no single tree to read, but it can still tell us which predictors mattered.

  • Impurity importance: add up how much each predictor reduced the Gini impurity (or the variance, for regression) across every split that used it, in every tree.
  • Permutation importance: shuffle one predictor’s values and measure how much the out of bag error rises. A predictor the forest relies on makes the error rise a lot.

Limitations

  • Like bagging, a random forest is much harder to interpret than a single tree.
  • It can be slow to train on large datasets with many trees.
  • It extrapolates poorly beyond the range of the training data, like most tree based methods.

Random Forests in R

We fit random forests with the ranger package, through caret::train() with method = "ranger". Three settings can be tuned:

Setting What it controls
mtry How many predictors are drawn at each split
splitrule How each split is chosen: "gini" for classification, "variance" for regression
min.node.size When a node stops splitting, which controls how deep each tree grows

The number of trees, num.trees, is not tuned. More trees never hurt a forest; they only take longer.

Tuning mtry

A random forest needs two things that pull against each other:

  1. Strong trees, each able to predict well.
  2. Diverse trees, which make different mistakes so that averaging helps.

mtry sets the balance:

  • A small mtry adds more randomness: more diverse trees, but each one is weaker.
  • A large mtry gives stronger trees that look more alike. At the maximum, it is bagging.

Tuning min.node.size

min.node.size sets when a node stops splitting. With min.node.size = 5:

  • A node with 5 or fewer observations is not split. It becomes a leaf.
  • A node with 6 or more can still split, so leaves can end up smaller than 5. A node of 7 can split into 6 and 1.
  • In classification, a leaf that stops early can hold both classes, say 3 to
    1. Its vote is the majority class.

Smaller values grow deeper trees, and larger values grow shallower ones.

The defaults are 1 for classification and 5 for regression. With 1, a tree keeps splitting until nearly every leaf holds a single class. Forests usually do well with deep trees, since averaging removes much of their variance.

The Personality Data Again

The same data, split, and target as the decision tree and bagging lectures: predicting OPN8, “I use difficult words,” from the other 49 items.

data <- read.csv("data/data-final-shuffled.csv")

# items coded 0 and 1, and items stored as text, are categories
dichotomous_vars <- colnames(data)[sapply(data, max) == 1]
character_vars   <- colnames(data)[sapply(data, class) == "character"]
cat_vars         <- c(character_vars, dichotomous_vars)
data[cat_vars]   <- lapply(data[cat_vars], as.factor)

target <- "OPN8"

set.seed(123)
split      <- initial_split(data, prop = 0.7, strata = target)
data_train <- training(split)
data_test  <- testing(split)

The Recipe and the Grid

These data have no missing values, so the recipe only dummy codes the factors. The grid tries five values of mtry, from very random to close to bagging.

blueprint <- recipe(OPN8 ~ ., data = data_train) %>%
  step_dummy(all_nominal_predictors())

rf_grid <- expand.grid(
  mtry          = c(2, 4, 7, 15, 30),
  splitrule     = "gini",
  min.node.size = c(1, 5)
)

Fitting the Forest

Each of the 10 combinations is fit in each of the 10 folds, with 500 trees per forest.

set.seed(559)

rf_model <- train(
  blueprint,
  data       = data_train,
  method     = "ranger",
  metric     = "Kappa",
  trControl  = trainControl(method = "cv", number = 10),
  tuneGrid   = rf_grid,
  num.trees  = 500,
  importance = "impurity"
)

Tuning Results

ggplot(rf_model) + theme_minimal(base_size = 13)

Cross validated Kappa is highest with mtry = 15 and min.node.size = 5.

Wrapping Up

  • Bagging averages many trees, but trees that look alike limit how much averaging can help.
  • Random forests make the trees less alike by drawing a random subset of predictors at each split.
  • mtry balances strong trees against diverse trees. With mtry equal to the number of predictors, a random forest is bagging.
  • The out of bag observations give a built in error estimate, and impurity or permutation importance shows which predictors mattered.
